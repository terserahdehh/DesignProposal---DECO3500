The hardware contains no GPS or magnetometer. A laptop location represents that laptop; giving both bands the same laptop position cannot locate two separately moving people. Each wearer should use their own Android Chrome phone, connect their own band and select **Keep location updated**. A reported north-up arrow needs a compass for orientation. Poor/overlapping GPS accuracy suppresses the bearing. Vercel hosts the frontend; it supplies neither GPS coordinates nor a radio relay.

Web Bluetooth requires a secure context and a supported browser, as described in [Chrome's Bluetooth documentation](https://developer.chrome.com/docs/capabilities/bluetooth). Modern Chrome may also request [Local Network Access](https://developer.chrome.com/blog/local-network-access) for the USB bridge. Ordinary iPhone browsers do not support the Direct Bluetooth flow. A plain HTTP page at a laptop LAN address usually cannot request browser location; use HTTPS or localhost.

## Issues reproduced and fixed test-first

- Bluetooth complete status updates could retain a previous bearing after firmware omitted expired guidance. Merge logic now removes it.
- `/phone` ignored unsolicited `message`, `sent`, `send_failed` and `dismissed` Bluetooth events. Custom messages now update the physical band state immediately.
- USB snapshots discarded the device sequence for repeated messages. They now retain it so the browser can show the next popup even when text repeats.
- Browser transports accepted old/future/fractional location timestamps. Shared validation rejects them; queued Bluetooth writes revalidate before transmission.
- Continuous browser location watching remained active after a band disconnect. The page clears the watch and rejects late callbacks.
- A contradictory top-level/nested owner in a Bluetooth hello could enable configuration. Handshake now rejects conflicting identities.
- The deployed `/phone` endpoint returned HTTP 404 before this deployment, despite the local route rewrites already being present. The complete current frontend is being redeployed.

The `/phone` live status card and incoming popup are added with expiry, peer availability and reported quality checks. A browser popup can be hidden independently of the physical watch's unread state. Public HTTPS pages start with Direct Bluetooth; localhost starts with USB.
